## Best practices implementation
- Concevoir les colonnes batch comme un contrat durable et extensible, avec valeurs enumerees ou normalisees pour eviter les etats libres difficiles a requeter.
- Garder l'ecriture d'etat idempotente et monotone autant que possible pour limiter les regressions lors de reprises worker ou retries provider.
- Indexer les lectures operateur sur `tenant_id`, `status`, `processing_strategy`, `provider_batch_state` et `updated_at`.
- Exposer des helpers serveur centraux pour lire et ecrire les transitions batch afin d'eviter les divergences entre processor, worker et UI.
