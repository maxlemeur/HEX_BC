## Best practices implementation
- Supabase / Postgres : stocker hypotheses, demandes de pieces et changements de statut dans un journal exploitable par audit, sous RLS multi-tenant sur l'affaire et la version.
- Supabase / Postgres : indexer toutes les FK de registre (`project_id`, `version_id`, `source_document_id`) et prevoir un partial index sur les statuts `open` / `critical` si la gate de validation les lit en priorite.
- Supabase / Postgres : utiliser une pagination par curseur pour les registres longs afin d'eviter les `OFFSET` couteux sur l'historique des hypotheses.
- Next.js : rendre la lecture principale en Server Component et reserver les mutations `confirmer`, `resoudre`, `demander une piece` a des Server Actions explicites.
- UX / accessibilite : les filtres de severite et d'etat doivent etre deep-linkables, les libelles doivent expliciter le risque metier, et les alertes critiques ne doivent pas reposer uniquement sur la couleur.
