## Best practices implementation
- Implementer les actions operateur comme commandes idempotentes et autorisees cote serveur, jamais comme logique implicite cote client.
- Exiger une precondition d'etat avant execution pour eviter les transitions illegales ou les doubles resoumissions.
- Tracer auteur, raison et resultat de chaque action de remediation dans un audit trail lisible.
- Prevoir des gardes explicites pour les jobs deja terminaux ou deja repris par un autre processus.

## Notes execution
- Execution realisee le 9 mars 2026.
- Decisions techniques:
  - EST-427 garde le contrat de statuts lisibles EST-426 pour le hub, et ajoute un contrat secondaire `operatorState` pour piloter les CTA operateur sans reintroduire les statuts provider bruts partout.
  - Permissions retenues: `admin` + `engineer` peuvent executer `relancer reconcile`, `annuler`, `resoumettre`; `viewer` reste strictement en lecture seule.
  - `resoumettre` reinitialise le meme job au lieu de creer un nouveau job. Le reset nettoie les champs batch/reconcile/erreur courants, incremente `retry_count`, puis retrigger le worker existant.
  - `relancer reconcile` ne resoumet jamais le provider: la commande force `provider_reconcile_due_at = now`, nettoie une lease stale si necessaire, puis relance le worker `reconcile`.
  - Audit ajoute:
    - `takeoff.job.reconcile_requested`
    - `takeoff.job.resubmitted`
    - `takeoff.job.canceled` conserve
