# EST-264 - Benchmark performance editeur

## Objectif
Valider que l'editeur de devis reste fluide avec de gros volumes (1000 a 3000 lignes) sans regression fonctionnelle.

## Scope implemente
- La page `src/app/dashboard/estimates/[versionId]/edit/page.tsx` calcule maintenant une configuration memoisee pour la table editeur.
- La prop optionnelle `virtualization` est transmise a `EstimateEditorTable` avec shape stable:
  - `enabled: boolean`
  - `rowEstimate: number`
  - `overscan: number`
  - `maxHeight?: number`
- Le composant `src/components/estimates/EstimateEditorTable.tsx` prend en charge:
  - flatten des lignes visibles
  - rendu virtualise via `@tanstack/react-virtual`
  - fallback sur rendu non virtualise si feature flag desactive
  - memoisation des structures de rendu couteuses
- Hook ajoute: `src/hooks/useVirtualList.ts`.
- Comportement par defaut inchange: virtualization desactivee tant que `NEXT_PUBLIC_ESTIMATE_EDITOR_VIRTUALIZATION_ENABLED` n'est pas active.

## Parametrage de test
Variables client (optionnelles):

```bash
NEXT_PUBLIC_ESTIMATE_EDITOR_VIRTUALIZATION_ENABLED=true
NEXT_PUBLIC_ESTIMATE_EDITOR_VIRTUALIZATION_ROW_ESTIMATE=56
NEXT_PUBLIC_ESTIMATE_EDITOR_VIRTUALIZATION_OVERSCAN=8
# optionnel
NEXT_PUBLIC_ESTIMATE_EDITOR_VIRTUALIZATION_CONTAINER_HEIGHT=720
```

Mode baseline (avant comparaison):
- Ne pas definir `NEXT_PUBLIC_ESTIMATE_EDITOR_VIRTUALIZATION_ENABLED` (ou la mettre a `false`).

Mode experiment (EST-264):
- Definir `NEXT_PUBLIC_ESTIMATE_EDITOR_VIRTUALIZATION_ENABLED=true`.

## Procedure manuelle de benchmark
1. Construire et lancer en mode production:
```bash
npm run build
npm run start
```
2. Ouvrir un devis de reference avec ~3000 lignes dans `.../dashboard/estimates/[versionId]/edit`.
3. Dans Chrome DevTools > Performance:
- Activer screenshots.
- Enregistrer un profil depuis l'ouverture de l'onglet **Editeur** jusqu'a la fin du premier rendu.
- Refaire un profil pendant 10 secondes de scroll continu.
4. Dans React DevTools Profiler:
- Capturer une session sur: chargement onglet Editeur, changement de filtre qualite, edition d'une ligne.
- Exporter le profil JSON (avant/apres).
5. Verifier les operations fonctionnelles (pas de regression):
- Ajout section, ajout ligne, suppression ligne, reorder, edition inline, filtre qualite.

## Cibles a atteindre

| Mesure | Cible | Outil |
| --- | --- | --- |
| Rendu initial (1000 lignes) | < 100 ms | React DevTools Profiler (commit principal) |
| Chargement initial (3000 lignes) | < 500 ms | Chrome Performance (navigation -> premier rendu interactif) |
| Scroll 3000 lignes | ~60 FPS, sans jank visible | Chrome Performance (frames proches de 16.6 ms) |
| Long tasks pendant scroll | 0 critique, max 3 > 50 ms sur 10 s | Chrome Performance |
| Regressions fonctionnelles | 0 | Verification manuelle |

## Format de restitution recommande
Pour chaque campagne (baseline vs experiment), documenter:
- Date / navigateur / machine
- Volume de lignes
- Valeurs de `virtualization`
- Metriques observees (tableau)
- Captures: trace Chrome + export React Profiler
- Conclusion: `PASS` ou `FAIL` par cible

## Notes
- La configuration de virtualization est memoisee pour conserver une reference stable entre renders.
- Lorsque `enabled=false`, le rendu reste non virtualise et le comportement metier est inchange.
- `NEXT_PUBLIC_ESTIMATE_EDITOR_VIRTUALIZATION_CONTAINER_HEIGHT` alimente `virtualization.maxHeight` dans le composant.
