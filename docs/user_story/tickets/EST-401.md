## Best practices implementation
- Charger l'etat initial `presence + threads` depuis un Server Component, puis hydrater uniquement le panneau de commentaires et les actions interactives.
- Appliquer une RLS stricte sur les threads et commentaires d'affaire, avec index sur `project_id`, `scope_type`, `scope_id`, `last_message_at` et les colonnes FK de participants.
- Utiliser une pagination par curseur pour l'historique des fils et conserver le thread actif dans les query params pour permettre le deep-link et le retour navigateur.
- Annoncer nouveaux messages et mentions via `aria-live` sans voler le focus, et garder la presence visuelle non bloquante pour le cockpit principal.
- Passer les ouvertures de thread, filtres et changements d'onglet en `startTransition`, avec payload client limite aux champs utiles de lecture et de statut.
