## Best practices implementation
- Supabase / Postgres : activer une RLS stricte sur les documents d'affaire et indexer `project_id`, `classification_status`, `document_kind` et les cles de jointure utilisees par le triage.
- Supabase / Postgres : prevoir un partial index pour la file `a revoir` ou `classification ambiguous` afin d'eviter un scan complet des imports incomplets.
- Next.js : conserver les lectures initiales de dossier et de resume de classement en Server Components ; reserver les mutations de correction / validation a des Server Actions ou a un route handler uniquement si un connecteur externe l'impose.
- React / perf : lancer en parallele extraction, OCR et classement independants quand c'est possible, puis ne pousser au client qu'un resume exploitable plutot que la totalite du graphe documentaire.
- UX / accessibilite : la dropzone doit etre pilotable au clavier, annoncer la progression et les erreurs fichier par fichier en `aria-live`, et conserver un deep-link vers le filtre `a revoir`.
