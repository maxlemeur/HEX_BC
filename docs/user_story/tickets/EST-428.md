## Best practices implementation
- Valider le type de document a plusieurs niveaux: navigateur, serveur et lecture effective du contenu.
- Privilegier l'echec explicite quand le document n'est pas lisible de facon fiable, plutot qu'une pseudo-reussite non defendable.
- Differencier clairement parsing technique, lisibilite documentaire et exploitabilite metier.
- Capturer les motifs de rejet dans un format stable pour l'analyse pilote et le support.

## Notes execution
- Decisions techniques
  - Centralisation de la validation PDF dans `src/lib/takeoff/pdf-validation.ts` pour partager le fallback MIME/extension et la lecture effective du contenu entre UI, serveur et processor.
  - Fallback PDF autorise uniquement quand le MIME est vide ou notoirement peu fiable (`application/octet-stream`, variantes assimilables) et que l'extension `.pdf` est presente.
  - Les uploads mono-fichier Level `B/C` valident maintenant les vrais octets PDF avant creation du job; un PDF invalide echoue en `TAKEOFF_PDF_CORRUPTED` avant stockage.
  - Le processor Level `B` n'utilise plus de succes degrade silencieux quand le PDF n'est pas lisible de facon fiable.
  - L'exploitabilite metier devient explicite:
    - Level `B`: echec `TAKEOFF_PDF_NOT_INTERPRETABLE` si aucun tableau exploitable n'est persiste.
    - Level `C`: echec `TAKEOFF_PDF_NOT_INTERPRETABLE` si aucun item exploitable n'est produit.
- Risques residuels
  - La detection "PDF interpretable" reste heuristique cote metier: un document OCR pauvre peut passer la lecture technique mais echouer plus tard cote extraction.
  - Les messages utilisateur reposent sur `pdf-lib`; un export PDF exotique mais lisible par un autre moteur peut etre classe corrompu ici.
  - Les tests processor restent sensibles aux fixtures PDF irreelles; toute nouvelle fixture `%PDF...` simplifiee risque maintenant de produire un faux negatif.
- Mitigations
  - Utiliser des fixtures PDF generees via `pdf-lib` dans les tests touches par les flux `B/C`.
  - Conserver les codes stables `TAKEOFF_PDF_CORRUPTED` et `TAKEOFF_PDF_NOT_INTERPRETABLE` pour le support, le monitoring et l'analyse pilote.
  - Ne pas elargir le fallback MIME aux extensions non PDF sans validation metier explicite.
