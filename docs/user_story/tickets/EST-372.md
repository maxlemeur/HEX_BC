## Best practices implementation
- Supabase / Postgres : indexer `project_id`, `source_document_id`, `status` et les cles de provenance du brief ; utiliser un partial index sur les items `a_confirmer` si cette vue devient la revue principale.
- Next.js : charger le brief, les sources et les manques depuis un Server Component, puis traiter les confirmations / edits via Server Actions pour garder les secrets et les validations cote serveur.
- Next.js / RSC : ne jamais passer au client des objets riches inutiles ; serialiser uniquement les champs visibles du brief et convertir dates / enums en formats stables.
- React / perf : recuperer en `Promise.all` les sections independantes du brief, puis streamer ou hydrater seulement les panneaux editables.
- UX / accessibilite : chaque phrase issue de l'IA doit exposer sa source, le statut `a confirmer` / `confirme` doit etre lisible sans couleur seule, et une regeneration doit annoncer son resultat en `aria-live`.
