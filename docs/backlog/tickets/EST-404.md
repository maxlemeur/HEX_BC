## Best practices implementation
- Supabase / Postgres : conserver un journal append-only avec RLS par affaire / equipe, et stocker explicitement le flag d'exclusion du dataset d'apprentissage pour les corrections sensibles.
- Supabase / Postgres : indexer `project_id`, `exception_id`, `status`, `created_at` et utiliser un partial index sur les corrections `eligible_for_learning = true` si la constitution du dataset lit surtout ce sous-ensemble.
- Next.js : servir les vues de journal et de synthese cote serveur ; reserver les bascules `inclure / exclure du dataset` a des Server Actions authentifiees et historisees.
- React / perf : recuperer en parallele le journal, les compteurs et les exclusions, puis ne passer au client que les champs utiles au tableau et aux confirmations.
- UX / accessibilite : les exclusions sensibles doivent demander une confirmation explicite, les filtres doivent rester deep-linkables, et les listes longues doivent garder un comportement stable au clavier.
